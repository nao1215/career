# Benchmarks

career is measured the way a user runs it, one process per call from start to exit, with [himorime](https://github.com/nao1215/himorime). himorime builds career (with `CGO_ENABLED=0`, as the Makefile does), runs each command in interleaved rounds, and reports latency, CPU time, peak RSS and, for the large resume, throughput in employers per second.

```console
$ go install github.com/nao1215/himorime@latest
$ make bench            # himorime run bench
$ make bench-compare    # himorime compare --against main bench
```

## Regression suite: himorime.yaml

`make bench-compare` checks main out into a temporary Git worktree, builds it and your working tree, and measures both in the same rounds, so a background job slows both revisions instead of one. `BASE=v0.2.5 make bench-compare` compares against another revision. `himorime run --filter 'generate 300 employers' bench` measures one benchmark, and `himorime run --tag smoke bench` only the small ones.

On a pull request, `.github/workflows/bench.yml` runs `himorime ci bench` the same way, with the base of the pull request as the base, on one runner. The job fails when a command is slower, uses more CPU time or more memory than the base beyond the tolerance in `himorime.yaml` with 95% confidence. A difference too close to call is reported as inconclusive and does not fail the job. The comparison is on the job summary page and the JSON report is kept as an artifact.

The size in a benchmark name is the number of employers in the resume. Each employer is one history of three projects (read by the cv and the work-history) and a join and a leave line (read by the japanese-resume), in Japanese and English. The resumes are generated by `gen.sh` before measuring, so no fixture is added, and both revisions run the working tree's `gen.sh`. The portrait is the committed `image/sample_japanese_man.jpg`.

| Benchmark | Commands | Measures |
|-----------|----------|----------|
| `version` | `career version` | starting career |
| `generate 3 employers` | `--template` cv, japanese-resume, japanese-resume with `--photo`, work-history, all | rendering a typical resume, where start-up and loading the embedded IPAex fonts dominate, and every template in one call |
| `generate 300 employers` | `--template` cv, japanese-resume, work-history | laying out a resume of 151 pages (cv, work-history) and 21 pages (japanese-resume) |
| `generate error` | a resume file that does not exist | the error path, exit 1 |

`career init` and `career templates` write a fixed starter file and a fixed list, and are not measured.

Numbers from different machines are not comparable; compare revisions on one machine, as `make bench-compare` and CI do.
